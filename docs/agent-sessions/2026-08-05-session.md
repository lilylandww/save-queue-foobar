## Goal

## Root causes found (in order)
1. **SDK not in pushed commit**: The commit that originally triggered CI (f52be23 on GitHub's
   `master`) used the foobar2000 SDK as a **git submodule** (kbuffington/foobar2000-SDK), but the
   workflow's `actions/checkout` had no `submodules:` key -> empty SDK dir -> MSB3202 for all
   SDK projects. The local working tree instead vendored the SDK as regular files (and staged a
   refactored component: dropped auto-save hooks, WTL, Directory.Build.*).
2. **Stale local tree**: The local staged tree lacked `third_party/WTL` and a working WTL
   include path; libPPUI/stdafx.h and helpers/foobar2000+atl.h require WTL headers.
3. **Toolset mismatch**: On `windows-latest` (image windows-2025-vs2026) the registered MSVC
   toolsets are only `v145` (14.51, HAS ATL) + ClangCL + driver toolsets. v142/v143 requests
   redirect to 14.44 (NO ATL) -> C1083 'atlbase.h'. `v144` is not registered -> MSB8020.
   Verified via throwaway diagnostic workflows (`diag.yml`, `diag2.yml`) + `-getProperty`.
4. **WTL include path override**: `Directory.Build.props` (ItemDefinitionGroup) is overridden by
   each project's own `AdditionalIncludeDirectories`. `Directory.Build.targets` is imported
   after the project body, so it wins (this was the mechanism master used, with a hardcoded
   `E:\code\...` path).
