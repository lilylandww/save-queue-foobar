  the checkout on the runner had no `foobar2000_SDK.vcxproj`, `foobar2000_sdk_helpers.vcxproj`,

  been pushed from this working tree. The previous CI run came from an earlier push that
  lacked the SDK.
- Latent bug found and verified empirically (via a throwaway `dotnet msbuild` repro in
  `/tmp/opencode/platform-map`): solution platform `x86` maps to project platform `Win32`, so
  the component `OutDir` (`build\$(Platform)\$(Configuration)\`) produces `build/Win32/<cfg>`
  for x86 builds — the workflow's artifact path `build/x86/<cfg>` would have found no files
  even after a successful build (`if-no-files-found: error`).
